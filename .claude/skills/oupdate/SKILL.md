# /oupdate — обновление Next version из чатов

Цель: собрать из чатов всё, что войдёт в следующую версию, записать это в файл Next version и запустить сборку через `/Oversion` (номер версии) и `/ostart` (старт сборки).

Не выдумывай содержимое версии. Всё, что попадает в файл, должно быть взято из чатов или подтверждено пользователем.

## Шаг 1. Источники чатов

По умолчанию брать:
1. Текущий диалог с пользователем.
2. Если пользователь назвал конкретные чаты, ветки, каналы или ссылки, — только их.

Если пользователь указал источник, который недоступен в этой среде (Slack, Telegram, claude.ai-чат), — скажи это одной строкой и продолжай с доступными источниками. Не придумывай содержимое недоступного чата.

## Шаг 2. Извлечение пунктов

Из чатов вытащи только то, что относится к следующей версии:
- **Фичи** — что нужно сделать или добавить.
- **Фиксы** — баги и их описания.
- **Решения** — что решили, что отбросили.
- **Открытые вопросы** — что ещё не решено.
- **Сроки и блокеры**, если они названы.

Правила:
- Дедуплицируй: одна и та же задача, упомянутая несколько раз, — один пункт.
- Для каждого пункта сохрани источник (дата или ссылка на сообщение, если есть).
- Если пункт неоднозначен, помечай его `[уточнить]`, а не угадывай.

## Шаг 3. Файл Next version

Записывай в `NEXT_VERSION.md` в корне репозитория. Если файл уже есть, читай его и обновляй, не затирая существующие пункты.

Структура:

```markdown
# Next version

Обновлено: <дата>

## Фичи
- [ ] <пункт> — источник: <...>

## Фиксы
- [ ] <пункт> — источник: <...>

## Решения
- <решение> — источник: <...>

## Открытые вопросы
- [уточнить] <вопрос>
```

Отмеченные пункты (`[x]`) не трогай. Они уже сделаны.

## Шаг 4. Версия через /Oversion

Вызови скилл `Oversion` через Skill tool и передай ему текст пунктов из `NEXT_VERSION.md`, чтобы он выбрал номер версии по своим правилам. Не определяй номер сам.

Если скилл `Oversion` не найден, остановись на этом шаге и сообщи пользователю. Не угадывай схему нумерации.

## Шаг 5. Сборка через /ostart

Вызови скилл `ostart` через Skill tool и передай ему версию из шага 4 и путь к `NEXT_VERSION.md`.

Если скилл `ostart` не найден, остановись и сообщи пользователю. Не запускай сборку вручную.

## Шаг 6. Отчёт

Коротко, по пунктам:
- сколько пунктов добавлено и сколько обновлено;
- какой номер версии выбран через `/Oversion`;
- результат `/ostart` (успех, ошибка или не запущен — и почему);
- список `[уточнить]`, которые надо решить до сборки.

Коммитить и пушить `NEXT_VERSION.md` только если пользователь попросил.
